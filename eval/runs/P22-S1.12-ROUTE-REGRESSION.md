## Baseline

```text
Before = FAIL
```

`P22-EVAL-03-FIRST-RUN.md` established that the deterministic router recognized all
four commands, but WebShell only executed `pause` directly. `继续播放`, `下一首`, and
`上一首` fell through to `ProviderAgentLoop.run()`.

## Root Cause Confirmation

Current bundle code confirms the same root cause:

```text
route_intent
  暂停     -> pause
  继续播放 -> play
  下一首   -> next_track
  上一首   -> previous_track

WebShellApp._run_chat
  -> _stop_family_fast_path
       pause / stop_preview => executed directly
       play / next_track / previous_track => returned None
  -> ProviderAgentLoop.run
```

The CLI/chat-session path already consumes the same deterministic routes directly,
including the existing suspension and running-preview rules. The divergence is at the
WebShell execution boundary, not in the router.

## Implemented Delta

`src/music_agent/web_shell.py` now reuses the existing fast-path boundary for the
closed playback quartet:

```text
pause
continue/resume -> play
next_track
previous_track
```

Preserved contracts:

- `pause` remains state-verified through `run_playback_control_attempt`.
- `continue/resume` reads `get_playback_context`; a running Preview reports progress;
  no suspension means `没有可恢复的播放。`; a valid suspension executes `play` and
  verifies `get_now_playing`.
- `下一首` during a running Preview routes to `advance_preview`, never Music.app.
- `下一首` off a Preview session routes to `next_track`.
- `上一首` keeps the existing `previous_track` route.
- closed-command context/action failures stay deterministic and do not fall back to
  Provider.

No second playback executor was added.

## Controlled WebShell Boundary Probe

The supplied bundle is partial, so the official project unittest suites cannot import
all project modules. A controlled probe executed the real extracted
`WebShellApp._run_chat`, `intent_router`, and `action_attempt` code; only bundle-omitted
imports were stubbed. `ProviderAgentLoop.run()` was configured to raise immediately if
invoked.

| command | actual_route / calls | provider_invoked | provider_rounds | action | readback | final_response |
|---|---|---:|---:|---|---|---|
| 暂停 | `get_playback_context -> pause -> get_now_playing` | false | 0 | `pause` | state=`paused` verified | `已暂停播放。` |
| 继续播放 | `get_playback_context -> play -> get_now_playing` | false | 0 | `play` | state=`playing` verified | `已继续播放。` |
| 下一首 | `get_playback_context -> next_track` | false | 0 | `next_track` | N/A — current navigation tool contract has no target readback | `已切换到下一首。` |
| 上一首 | `previous_track` | false | 0 | `previous_track` | N/A — current navigation tool contract has no target readback | `已切换到上一首。` |

Additional session/safety probes:

| scenario | observed behavior |
|---|---|
| `继续播放` with no suspension | no `play`; `没有可恢复的播放。`; provider rounds 0 |
| `继续播放` while Preview session running | no `play`; `连播进行中。`; provider rounds 0 |
| `下一首` while Preview session running | `get_playback_context -> advance_preview`; no `next_track`; provider rounds 0 |
| pause readback mismatch | no success claim; provider rounds 0 |
| next context read failure | no action; deterministic failure; provider rounds 0 |
| previous action failure | no success claim; provider rounds 0 |
